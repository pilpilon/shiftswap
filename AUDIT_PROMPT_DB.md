# ShiftSwap Architecture & Database Audit Prompt

**To the AI assistant:** 
You have been provided with the context and database schema of a SaaS application currently in development called "ShiftSwap". 
Please perform a comprehensive architectural, database, and security audit based on the information below.

## 1. Project Overview
**Name:** ShiftSwap
**Description:** An automated shift management and negotiation agent for restaurants and businesses.
**Core Flow:** 
1. Employees receive their weekly schedule and submit their upcoming availability via WhatsApp.
2. If an employee cannot attend a shift, they message the system via WhatsApp (e.g., "I can't work on Tuesday").
3. The system (via an AI agent powered by Google Gemini) understands the request, registers a shift cancellation, and automatically starts offering the shift to other eligible employees sequentially via WhatsApp.
4. The system logs negotiations, handles approvals/rejections, and alerts managers if a shift remains uncovered.

**Tech Stack:**
- **Backend:** Node.js, Express, TypeScript.
- **Database:** Firebase Firestore (NoSQL).
- **Messaging:** WhatsApp Multi-Device (via `@whiskeysockets/baileys`).
- **AI Processing:** Google Gemini (`@google/genai`).
- **Frontend:** React/Vite (Dashboard for managers).

## 2. Current Database Schema (Firestore)
The application uses the following collections and subcollections to manage state, users, and shift logic.

### Collection: `businesses` (Root Collection)
Represents a client workspace (e.g., a specific restaurant).
- **Document ID:** `businessId` (e.g., auto-generated or Firebase Auth UID)
- **Subcollections:**
  - `settings` / `rules`: Contains custom constraints for the AI (e.g., "Max instant bonus", "Taxis for closing shifts").
  - `lid_mappings`: Caches WhatsApp internal `@lid` identifiers to actual normalized phone numbers (`972XXXXXXXXX`).
  - `swaps`: Stores all shift swap requests.
    - Fields in a swap doc: `date` (string), `shiftTitle` (string), `role` (string), `originalEmployee` (string), `originalPhone` (string), `reason` (string), `status` ('pending' | 'covered'), `coveredBy` (string, optional), `urgency` ('high' | 'medium' | 'low'), `createdAt` (ISO string), `currentlyAsking` (phone string, used for the active offer lock), `rejectedBy` (array of phone strings).

### Collection: `staff` (Root Collection)
Represents employees across all businesses.
- **Fields:** `businessId` (string), `name` (string), `phone` (string, usually normalized to `972XXXXXXXXX`), `role` (string, e.g., 'waiter', 'מנהל').

### Collection: `availability` (Root Collection)
Stores employee availability submissions per week.
- **Path structure:** `availability/{businessId}/{weekKey}/{phone}` (where `weekKey` is e.g. "2026-W08")
- **Fields:** `days` (array of strings, e.g., ["ראשון", "שני"]), `notes` (string, optional), `submittedAt` (ISO string).

### Collection: `published_schedules` (Root Collection)
Stores the final weekly schedule generated by the manager.
- **Path structure:** `published_schedules/{businessId}/weeks/{weekKey}`
- **Fields:** `schedule` (Map/Dictionary of `phone` -> Array of `{ date, hours, role }`), `updatedAt` (ISO string).

### Collection: `negotiation_logs` (Root Collection)
Logs all chat messages between the employee and the system (AI or auto-responses) for auditing and context history.
- **Fields:** `businessId` (string), `employeePhone` (string, JID), `message` (string), `sender` ('ai' | 'employee' | 'system'), `timestamp` (ISO string).

### Collection: `auth_state` (Root Collection)
Stores the raw WhatsApp Baileys authentication keys and session state per business (critical for maintaining WhatsApp web sessions across server reboots).
- **Document ID:** `businessId`

## 3. Security & Logic Context
- **Authentication:** WhatsApp messages are authorized by verifying the sender's phone number against the `staff` collection. If the sender's JID is not in the staff list, the message is ignored.
- **LID Resolution:** WhatsApp Multi-Device sometimes masks numbers as `@lid`. To resolve this, the system fuzzy-matches the WhatsApp `pushName` against the `staff` collection's names, caches the mapped phone in the `businesses/{businessId}/lid_mappings` subcollection, and proceeds.
- **Concurrency:** The system iterates over eligible staff to offer shifts. The `swaps` document uses a `currentlyAsking` field to track who currently holds the active offer, preventing the AI from offering the same shift to multiple people simultaneously and causing double-booking.
